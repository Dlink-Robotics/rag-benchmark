# Instructions for AI coding assistants

These rules apply to any AI assistant that works in this repository. They repeat the key rules of [CONTRIBUTING.md](CONTRIBUTING.md), which you must read first. If this file and CONTRIBUTING.md disagree, CONTRIBUTING.md and the repository settings win, and this file should be fixed.

## Before you change anything

1. Read [CONTRIBUTING.md](CONTRIBUTING.md).
2. Check the current branch with `git branch --show-current`. If it is `main`, make a branch first. `<name>` is the person you are working for.

   ```sh
   git switch main
   git pull
   git switch -c <name>/<topic>
   ```

Never edit, commit or push on `main`. GitHub refuses a push to `main`, so work done there is wasted.

## Rules

- **Titles.** Issues, pull requests and commits use `<type>: <short description>`. Types: `feat`, `fix`, `docs`, `test`, `perf`, `ci`. Lowercase, imperative, no full stop, about 72 characters or fewer.
- **Commits.** Do not add an AI name as co-author, and do not add "generated by" lines.
- **One change per pull request.** Show the diff to the person before you push.
- **Review.** Open the pull request and ask a different person to review it. Do not approve any pull request. Do not merge one unless the person tells you to.
- **No force pushes.** Delete only your own merged branch.
- **Settings.** Do not change repository settings, rules, collaborators, secrets or security settings unless the person explicitly asks for it in the same conversation.
- **Never commit** secrets, API keys, `.env` files, the held-out test questions, personal data, large model files or machine-specific paths. If you find one already committed, stop and tell the person.
- **Numbers.** Numbers in a pull request description must come from a command that you ran. Say which command and which machine. Never invent or estimate a result.
- **If you are unsure, ask.**
