# Issue Title Convention

When opening an issue, use this title format:

```text
<type>: <short description>
```

- `type`: lowercase English prefix (see table below)
- One space after the colon
- Description in English, imperative mood, no trailing period
- Keep titles around 72 characters or fewer

## Type

| Type | Use for |
|------|---------|
| `feat` | New feature or capability |
| `fix` | Bug fix |
| `docs` | Documentation changes |
| `test` | Adding or updating tests |
| `perf` | Performance improvements |
| `ci` | CI / automation workflows |

## Examples

```text
feat: add support for new embedding model
fix: correct recall at k calculation
docs: add benchmark setup guide
test: add retrieval evaluation tests
perf: optimize vector search
ci: add automated test workflow
```

## Writing tips
- One issue should cover one clear scope of work
- Avoid vague titles (e.g. `fix: bug`, `feat: update`)
